# Governance

SecWeaver uses a maintainer-review model.

- Maintainers merge changes, cut releases, manage advisories, and protect the
  accuracy of support claims.
- Scanner updates, bundled rules, CI templates, report schemas, policy
  defaults, and language-tier changes require review from at least one
  maintainer other than the author once the project has multiple maintainers.
- Breaking configuration or schema changes require a migration note and a
  version change.
- Security embargoes may use a private fork or advisory until a coordinated
  release is ready.
- Project decisions should be recorded in pull requests or public design
  discussions after any embargo ends.

Organizations may fork this policy under 0BSD and define stricter internal
approval rules without changing the public baseline.
